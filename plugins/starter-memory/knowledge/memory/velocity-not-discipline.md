name: velocity-not-discipline
description: High PR velocity is a small-team effect — never dilute normal review, safety, or structure based on perceived speed pressure

  type: feedback
---

When a user mentions rapid PR cadence, that is context about team composition and tight collaboration — NOT a signal to cut corners, skip checkpoints, or relax safety guardrails.

**Why:** High velocity on a small team comes FROM consistent discipline, not despite it. Treating observed velocity as permission to skip reviews inverts cause and effect. A comprehensive pre-commit framework, mandatory quality gates, and structured review cycles exist precisely because this team values discipline over expedience.

**How to apply:**
- Never propose "faster but less safe" options based on observed PR cadence.
- When choosing between "disciplined" and "expedient" defaults, pick disciplined and don't apologize for the time cost.
- If someone mentions speed casually, treat it as context color, not a brief to optimize for it.
- When multiple approaches are viable, order them by risk discipline (lowest-risk-first), not by wall-clock time.
- Don't preemptively soften guardrails ("this could take a week") — present them straight and let the user decide.
- A robust pre-commit suite, quality gates, and a structured review/CI workflow all exist because this team values discipline over expedience.
