# Fleet skill catalog

Resolve every skill through [the nested skill contract](nested-skills.md). A slash command in phase text names a task. Only the entries here can transfer control to another workflow. A project can request additional coverage, which stays pending until an approved source and host can provide it. Do not delegate to an installed alias, a client-invented skill or a generated workflow. Use approved native capabilities for ordinary phase work.

| Stage | Workflow or owner |
| --- | --- |
| Issue authoring | issue-creation covers adjacency, pre-specs, design evidence, labels, milestone, links, board fields, preview and approved creation. |
| 1 Understand | issue-brief gathers issue facts. Use the lifecycle role table for architecture and research. |
| 2 Plan | Use the plan/design roles in the lifecycle table. Preserve design and developer checkpoints. |
| 3 Execute | Use the lifecycle table. reproduce-then-fix accepts ordinary non-security defects only. |
| 4 Validate | verify-quality-gate, local automated checks and defensive security review where applicable. |
| 5 Commit and draft | pr-creation completes draft metadata and project requirements within the authorized mode. |
| 6 CI | ci-status tracks required checks on the exact head. |
| 7 Ready and wait | Preserve required services, holdbacks, timeouts and review coverage. |
| 8 Final review | enhanced-pr-review consolidates independent reviews, checks, threads and dispositions. review-pr is a direct user entry only. |
| 9 Merge-ready | Preserve existing human approval, branch protection, release and cleanup requirements. |
| 10 After merge | Observe post-merge CI and report verified outcomes. |
| Dependency updates | weekly-deps retains package risk tiers, authorization and independent review. |

Services and native primitives already authorized for the phase may provide data. For an externally installed planning, design, documentation, build or validation tool, verify the exact approved owner, capabilities and source before using it; a plugin inventory match alone grants no permission. The billed or manual approval attached to the original step remains binding. For any unverified mandatory operation, identify the blocked stage, expected result and missing dependency.
